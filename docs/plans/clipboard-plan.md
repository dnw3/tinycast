# 剪贴板改进 Plan

2026-10-18 对照 [Maccy](https://github.com/p0deje/Maccy)（MIT，本地 `~/code/github/Maccy`）逐项读两边代码后定下。
只借鉴思路和行为，不复制代码，也不引入它依赖的第三方库。剪贴板是上游功能，这里的改动会增加同步冲突，
所以每一项都要说明动到的上游文件，并登记到 [fork-maintenance](../fork-maintenance.md)。设计原则：简洁、易用，
不为改进新增常驻界面或设置项。

## Tinycast 已经更好的地方（不能退化）

- SQLite trigram FTS 加上内存只留最近 1000 条；Maccy 全量载入内存、在主线程线性搜索。
- 图片存为独立 PNG，转码在后台；OCR 在 helper 进程里、默认关闭、空闲时才做。Maccy 每捕获一张图都在主进程跑 Vision。
- 文件条目只引用不复制，拒收临时目录，单次最多 32 个；先读 fileURL 再读文字。
- Timer 用 `.common` 模式，快速用户切换时停止轮询；数据库损坏时删库重建而不是崩溃。
- 识别 `com.apple.is-sensitive`，清空历史保留置顶，Copy Text 校验 `changeCount`，有不激活目标的原地粘贴。
- `ClipboardDefaultAction` 一处定义各快捷键的行为。

## 实施

### 第一批：低风险

- [x] 合成的 ⌘V 跟随当前键盘布局（Dvorak 等布局原先发出的是 ⌘K）；⌘ 切回 QWERTY 的布局仍用 ANSI 键码。
- [x] 补齐忽略的 pasteboard 类型：`org.nspasteboard.AutoGeneratedType`、旧版 1Password、KeeWeb、TypeIt4Me 等。
- [x] 捕获 JPEG / HEIC 图片，与 TIFF 一样在后台转成 PNG。
- [x] 修复图片异步写入的过期问题：转码期间关闭功能、暂停或清空历史后不再写入，并删掉孤儿 PNG。
- [x] 暂停记录：会话级状态，不持久化；启动器命令「暂停或恢复剪贴板记录」切换（命令目录不支持随状态变化的标题），
      HUD 确认，剪贴板界面只显示一行安静的「已暂停记录」。暂停期间的复制在恢复后不会补录。
- [x] 搜索命中高亮，预览从命中位置附近开始截取。

### 第二批：存储

- [x] 全历史去重：相同文字或文件、相同 PNG（SHA-256）移到最上面而不是新增一条；置顶条目只更新时间。
      新增内容哈希列和索引，旧行留空、不回填（后台回填可能与主连接争锁），随保留期自然淘汰；
      被顶上来的条目保留原来的来源 App。
- [x] 长文本不再静默丢弃：上限提高到 1,000,000 字符，FTS 只索引前 32,000 字符，旧库在一个事务里迁移，
      失败回滚、保留旧触发器。
- [x] 设置页显示历史占用的磁盘空间。已有按时间保留，不再加「最多条数」，避免设置变复杂。

### 第三批：富文本（已完成）

之前只存纯文本，从网页、Pages、Word 复制的格式会丢，「纯文本粘贴」对文本条目和普通粘贴没有区别。
2026-10-18 完成，并实测从历史复制写回 RTF。完成情况：

- [x] 只在文本分支读 `public.rtf`，超过 2 MB 的 RTF 丢弃、纯文本照常记录；文件、图片、颜色不受影响。
- [x] `rich_path` 列沿用 `ALTER TABLE` 轻量迁移；RTF 以 `.rtf` 存在 `imagesDir` 内，`owns`、删除、
  清空、保留期清理一并删除，删除时从 `DELETE … RETURNING` 取回路径，避免调用方持有旧副本漏删。
- [x] 行立即插入，RTF 离开主线程写入，落地前复查与图片相同的状态，并用每条目令牌保证最新一次复制胜出；
  落败的写入删除自己的文件。
- [x] 去重仍按纯文本哈希；重复复制保留原行，sidecar 跟随最新一次：有 RTF 则替换（内容相同不重写），
  没有则删除。这样一行永远等于最后一次复制的样子，规则只有一条。
- [x] 粘贴同时写 `.rtf` 与 `.string`（及内部标记），sidecar 丢失时退回纯文本；「纯文本粘贴」只写 `.string`。
- [x] 详情信息行类型显示「富文本」；不新增设置。备份与导入不带 RTF，恢复的行是纯文本。
- [x] harness 覆盖：捕获与归属、删除/清空/保留期、超限丢弃、去重、粘贴写回、旧库迁移、过期写入丢弃。

取舍：与去重分开一轮做，便于定位问题；只存 RTF，不存 HTML（体积大，可能带外部资源链接），webarchive 一类排除；
备份导出不带 RTF，拖出仍只给纯文本，HTML、RTFD 暂不支持。

## 不采纳

- 条目编辑、按复制次数排序、多选粘贴栈：与 Tinycast 的交互模型不一致。
- 可配置的轮询间隔、正则忽略规则、退出时清空：收益小于新增设置项的复杂度，有需要再评估。
- Maccy 的置顶字母快捷键：会限制置顶数量。

## 其他

同一次对比发现 4 处设置页使用 SwiftUI `.confirmationDialog`，违反「对话框只走 `DialogController`」：
剪贴板、通用、MCP、AI 提供方的确认框，已改为 Tinycast 自己的确认框。
