# 磁盘清理 Spec

状态：规划中，尚未实现。实施顺序与验证记录见 [Plan](cleanup-plan.md)；实现后的不变量以
[功能文档](../features/cleanup.md) 为准。

## 目标与范围

把 [Purge](https://github.com/jithin-sabu/purge-app)（MIT）的磁盘清理能力整合进 Tinycast，并且比 Purge 更强：

- **清完真的释放空间。** Purge 把所有东西移到废纸篓，而且从不清空，所以清理后磁盘空间不会变多。这里改为按处置方式分级。
- **覆盖更全。** Purge 只显示它认识的缓存；这里列出全部缓存，没审计过的标为需确认。
- **按工具自己的方式清理。** Docker、pnpm、Go、Homebrew、模拟器这类工具自管的资源，调用它们自带的命令，不直接删目录。

分四期交付：核心清理、深度清理、磁盘空间分析、自动化。不装常驻的 root 辅助进程，不发系统通知；只有系统更新残留一项在用户确认后请求一次系统管理员授权。
调研依据：Purge 源码及其 [safety-notes](https://github.com/jithin-sabu/purge-app/blob/main/docs/safety-notes.md)
记录的 10 起事故，以及 Mole、CleanMyMac、Lemon、Pearcleaner 的做法和已知问题。

## 交互

清理界面是 palette 子屏，布局和剪贴板、文件搜索一样：左边列表，右边详情。

```text
‹  搜索清理项…
▸ 磁盘概览     38.6 GB │ 可清理
系统与应用             │ 38.6 GB
☑ 应用缓存    4.1 GB › │ ▕██████▒▒░░░░░░░▏
⊟ 其他应用缓存 1.2 GB › │ 已用 348 GB · 可用 112 GB
浏览器                 │
☑ Chrome      2.3 GB › │ 开发工具    21.4 GB
🔒 Safari  正在运行     │ 系统与应用   5.3 GB
开发工具               │
☑ Xcode 编译缓存 12.3 GB›│ 上次清理 3 天前 · 累计释放 126 GB
≡                 清理 23.6 GB ↵  │  操作 ⌘K
```

**主屏布局**

- 第一行「磁盘概览」，打开时默认选中。详情区显示可清理量、容量条（已用 / 已选 / 可用）、各类别小计、上次清理时间和累计释放量。
- 没有完全磁盘访问权限时，顶部多一行访问提示。选中这一行时，主按钮变成"打开隐私设置"。
- 其余行按类别分节，每个可清理项占一行。行首是三态勾选框（全选 / 未选 / 部分），然后是标题和大小；能展开明细的行末尾带 `›`。
- 应用运行中、项目正在使用、缺少权限的行会加锁，变暗显示，tooltip 写明原因，并且永远不能被勾选。锁定状态实时计算。

**右侧详情**依次显示：

- 名称和磁盘占用大小；
- 处置方式，例如"可放心清理 · 直接删除""需确认 · 移到废纸篓""通过 Docker 清理"；
- 一段说明：这是什么、删除后会怎样；
- 位置、包含的内容、最近使用时间、如何重建；
- 如果是分组行，再列出其中最大的几项。

**键盘操作**

- ↵ 清理已勾选的项，必须先确认；⌘↵ 勾选或取消当前行。
- 进入明细：→（查询为空时）、⌘I、双击或 ⌘K「查看明细」。返回：←、Esc、查询为空时按退格。
- ⌘R 重新扫描，⌘F 在访达中显示，⌃⌘C 拷贝路径，⌥⌘, 打开清理设置。
- ⌘K 菜单另有：全选可放心清理 / 取消全选、退出该应用后清理、不再扫描此项、清空废纸篓…。

**明细**用同一套布局，例如逐个应用的缓存、逐个 DerivedData 项目。进入时按大小排序一次，返回后父级仍选中原来那一行。

**扫描**

- 每次打开都重新扫描。行逐个出现，大小随后流式填入；大小落定时不重排行。
- 摘要行显示"正在扫描…"。
- 留在清理界面期间保留结果；离开清理界面会取消扫描。

**确认与结果**

- 确认框写清楚几部分：直接删除多少、移到废纸篓多少、哪些交给工具命令、哪些因运行中而跳过。
- 确认后、执行前，会重新核对一遍"已勾选且未锁定"的集合。
- 执行时 HUD 显示固定文字"正在清理…"，可以取消。
- 完成后报告格式为"已删除 21.3 GB · 2.3 GB 移到废纸篓 · 跳过 3 项"。部分失败时逐项列出原因。
- 磁盘可用空间的变化只作辅助说明；变化明显偏小时，提示"部分空间要等本地快照过期后才会释放"。

**快速清理**是一条独立命令，不打开列表：扫描 → 确认 → 只清理"可放心清理"的项。

**磁盘空间分析**（第三期）用同样的布局：

- 根层列出主目录、应用程序、资源库，以及"其他"（已用空间减去已扫描到的部分）。
- 每行带比例细条。
- ↵、→、⌘I 进入下一层，←、Esc 返回，⌃X 移到废纸篓。

**设置页「清理」**包含：权限状态、删除方式、排除的位置、命令列表。之后几期再加入：闲置项目阈值、大文件阈值、定时清理、空间提醒、累计释放。

## 处置分级

| 级别 · 处置 | 适用 | 默认勾选 | 快速清理 / 定时清理 |
|---|---|---|---|
| 可放心清理 · 直接删除 | 审计表中能自动重建的缓存、日志、构建产物 | 是 | 是 |
| 需确认 · 移到废纸篓 | 未识别的缓存、Xcode 归档、个人文件、iOS 备份、残留、没有 lockfile 的项目产物 | 否 | 否 |
| 需确认 · 工具命令 | simctl、docker、brew、pnpm、go、tmutil | 否 | 否 |
| 需确认 · 移除下载 | 已上传到 iCloud 的文件的本地副本 | 否 | 否 |

设置里的「全部移到废纸篓」会把所有直接删除改为移到废纸篓，命令类不受影响。显示的大小是磁盘占用（allocated），
也就是删除后实际释放的空间，所以会和卸载界面显示的逻辑大小不同。

## 安全规则

1. 所有文件删除只经过一个纯函数策略 `CleanupSafetyPolicy.evaluate`。判断所需的事实全部作为参数传入：home、
   Tinycast 自身的 bundle ID、是否有完全磁盘访问权限、路径属性、解析后的真实路径、运行中的应用和可执行文件、当前时间。
2. 先查永不删除名单，再查审计过的例外。拒绝规则不区分大小写，放行规则精确匹配。符号链接不下钻；解析后逃出
   允许根目录的一律拒绝。Tinycast 各渠道自己的缓存永不列出。
3. 只有审计表里登记过的"可放心清理"项才会直接删除。命令类永远不算"可放心清理"，也永远不会自动执行。
4. 扫描时检查一次易变条件（应用是否在运行、项目是否正在使用、浏览器框架是否在加载），删除前再查一次。结论不缓存。
5. 没有完全磁盘访问权限时，不碰受保护的位置：容器、组容器、`.Trash`、Messages、Desktop/Documents/Downloads、
   iCloud。这样不会触发系统隐私弹窗；扫描也不触发 iCloud 下载。
6. 失败按 errno 写明原因，不静默跳过；结果如实报告。
7. 自动清理只处理审计过的"可放心清理"直接删除项，且必须未锁定、未被排除。开启自动清理的开关不进备份，也不进 `settings.json`。
8. Purge 的 10 起事故，以及 Mole / Lemon 记录的问题（appstoreagent、containermanagerd、e5bundlecache、
   FontRegistry、Spotlight、CloudKit、身份与钥匙串类缓存），每一条都对应一个 harness 断言。

## 清理范围

| 期 | 类别 | 内容 |
|---|---|---|
| 一 | 系统与应用 | **可放心清理**：`~/Library/Caches` 里已识别的缓存、更新残留、`~/Library/Logs`、崩溃报告、iOS 固件、30 天以上的已保存状态。**需确认**：其余未识别的缓存。**需要完全磁盘访问权限**：沙盒容器缓存、Messages 预览 |
| 一 | 浏览器 | Safari，以及 Chrome、Edge、Brave、Arc、Vivaldi、Opera 各配置目录的缓存；Firefox cache2。Service Worker 缓存需确认 |
| 一 | 开发工具 | Xcode 编译缓存与其他缓存；DeviceSupport（每个平台保留最新 2 个）；Xcode 归档（需确认）；约 30 种包管理器缓存；Gradle、Maven 等存储（需确认）；VS Code、Cursor、Zed、JetBrains 的缓存 |
| 一 | 废纸篓 | 显示大小；可从这里清空废纸篓 |
| 二 | 工具资源 | 模拟器、Docker / OrbStack、Homebrew、pnpm、Go、Time Machine 本地快照 |
| 二 | 闲置项目 | Purge 的 46 条规则加上 `CACHEDIR.TAG`。按闲置时长判断，正在使用的不列出，有 git 跟踪文件的不列出 |
| 二 | 文件 | 大文件和旧文件、重复文件、安装包、未完成的下载、macOS 安装器、本地 AI 模型、虚拟机、iOS 设备备份、iCloud 本地副本 |
| 二 | 系统更新残留 | `macOS Install Data` 与 `/Library/Updates`：仅当没有待装更新、内容早于当前系统安装时间时列出，跳过 `Locked Files`；需确认，执行时用一次系统管理员授权（先实测授权弹窗是否可接受，不可接受则只显示大小、说明并提供在访达中显示） |
| 二 | 残留与维护 | 已删除应用的残留、失效的启动项、旧扩展和旧 CLI 版本、重建缩略图缓存、重启程序坞 |
| 三 | 空间分析 | 逐层查看磁盘空间占用 |
| 四 | 自动化 | 定时清理、空间不足提醒（HUD + 菜单栏菜单行）、清理历史 |

**明确不做**：

- 精简语言文件或通用二进制；
- 清理 `/private/var/folders`；
- 重建 LaunchServices、`purge`、`periodic`；
- 钥匙串、账户、Spotlight、字体注册、CloudKit 相关的缓存；
- 损坏的偏好设置；
- 常驻的 root 辅助进程，以及除系统更新残留以外任何需要 root 的路径；
- 系统通知。

## 架构

`Features/Cleanup/{Model,Service,UI,Settings}` 是一个独立功能：

- `Model` 只依赖 Foundation，由 `cleanup-test` 直接编译。包括目录、安全策略、计划与选择、保留最新的规则、报告。
  它复用 `Uninstall/Model/UninstallProtection.swift` 里的 `PathFacts` 和实测过的 TCC 前缀表。
- `Service` 负责所有 I/O：`CleanupAccess`（原始读取）、`DiskUsageScanner`（`getattrlistbulk` 遍历、计算磁盘占用）、
  `CleanupScanner`、`CleanupRunner`、`CleanupSession`、`CleanupSettingsStore`。
- `UI` 里的 `CleanupCoordinator` 是唯一的动作入口，确认门放在它里面。

`AppCore` 持有 session 和 coordinator，`start()` 里不增加任何工作。新增的 palette 模式为 `.cleanup`、`.cleanupGroup`，
第三期再加 `.diskUsage`。命令由 `SettingsTab.cleanup` 拥有。设置项放在 fork 自己的 store 里，不改上游的
`AppSettings.swift`。删除方式和排除列表不进备份。没有新的 singleton、actor 或第三方依赖。从 Purge 改编的文件在首行注明出处，
并在 `NOTICE.md` 收录它的 MIT 声明。

## 验收

1. `cleanup-test` 覆盖：永不删除名单与例外、大小写与路径变体、符号链接逃逸、受保护名称、所有事故回归、目录审计
   （认领路径不重叠，每组只有一个级别，快速清理的范围严格等于审计过的直接删除项）、选择不变量、扫描代次、报告与
   errno 映射、全新 `UserDefaults` 下的默认值。
2. `cleanup-walk-test` 在临时目录里验证：磁盘占用和硬链接去重、不跟随符号链接、不可读目录、取消、只删内容时
   保留目录、扫描后才被换成符号链接的目标会被跳过。
3. 完整 run-tests、lint、Model 纯度检查、Debug 构建无新增警告，中文翻译补齐。
4. 原生验收：
   - 没有完全磁盘访问权限时不出现系统弹窗；
   - 大小与 `du` 吻合；
   - 运行中的应用会被实时锁定；
   - 确认框正确区分直接删除和废纸篓，移到废纸篓的东西能恢复；
   - 明细往返后选中行正确；
   - 快速清理可以取消；
   - 连续三轮使用后，内存相对基线增长不超过 10 MB；
   - 深浅色、中英文、三档界面尺寸下都正常。
5. 没有实际执行过的路径（真实工具命令、iCloud 移除下载等）单独记录，不写成已验证。
