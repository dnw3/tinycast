Tinycast · 内置代理 · 设计稿 v3 · 2026 年 10 月

先看见状态，再谈配置

现在的代理功能几乎全是配置：设置里四页表单，加上一层层弹出的编辑器。最常问的三件事是连着没有、走哪个节点、快不快，现在却要在启动器卡片、设置和节点列表之间拼着看。新设计参考了 Clash Verge Rev、Surge、ClashX 和 sing-box 的共同做法：状态放在最前，把节点、策略、分流三层画成一张流向图，日常操作放到菜单栏，管理收进独立的代理窗口，设置里只留偏好。数据模型、内核和 TUN 助手都不变。

状态在前每个入口先回答四件事：连着没有、出口在哪、多快、什么模式。
把三层画出来哪类流量走哪个策略，策略此刻用哪个节点，一张流向图看全。
一个模式开关规则、全局、直连三选一，取代「方案」和「临时全局代理」。
两步换节点菜单栏、启动器、代理窗口都能直接切换，不必进设置。

代理窗口 新增 · 管理节点、策略、分流和订阅的地方

和 AI 对话窗口同一种结构：系统侧边栏加统一工具栏，工具栏右侧的模式和开关在每一页都在。下面可以直接操作：切换侧边栏页面；改模式，看流向图怎么变；悬停流向图，看一类流量的完整路径；点一类流量改它的去向，点策略或出口跳到它的节点；在节点页点卡片换节点；在分流页拖动排序、在顶部输入网址看它走哪；在活动页给一条连接加规则。数据是示例，节点只节选了一部分。

窗口、菜单栏和启动器共用同一份状态，在任一处的改动会同步到其他地方。

菜单栏 新增 · 每天最常用的操作

独立的代理图标，和日历的菜单栏图标一样可以单独开关，菜单里只放代理自己的操作。模式三选一；每个策略一个子菜单，节点多的再按地区分一层，延迟靠右对齐并着色。分区标题、副标题和右侧角标都是原生 NSMenuItem 的能力（macOS 14 起提供，已对照 SDK 核对）。把指针移到策略和地区上展开子菜单，点节点即可切换，上面的窗口会跟着变。

图标即状态。连接时图标正常显示，可以在后面附上实时网速；断开时图标变淡。菜单顶部一行就是当前出口和延迟，不用展开任何东西。

启动器 保留 · 内容和文案调整

输入「代理」仍然先出状态卡，三栏改为出口节点、模式、连接，回车选择节点。「代理分流」「代理策略」两个列表屏幕去掉，命令改为打开代理窗口的对应页面；「添加代理规则」保留，因为它能读到当前浏览器的网址，这是窗口做不到的。

为什么这样改 现在的设计哪里不直观

没有首页“现在走哪、快不快”散在启动器卡片、设置通用页和节点列表里，要拼起来看。
→
概览出口、流量、流向、健康状况放在同一屏，打开窗口第一眼就是答案。
配置成了主体四页设置表单加六七个弹出编辑器，日常用不到的东西占满视野；表单行里的菜单还藏着上移、下移、关闭这些操作。
→
管理进窗口，偏好留设置节点、策略、分流、订阅各有一页，用卡片和列表直接操作；拖动排序，开关在行尾。
三层只能靠记节点、策略、分流分在三页，彼此的关系只出现在菜单标题里。用户得在脑子里把它们连起来。
→
流向图把“流量 → 策略 → 节点”画出来；节点页也标明每个策略用于哪些分流。
两个“全局”，没有“直连”「方案：全局代理」和「临时全局代理」意思不同；想临时不走代理只能断开，TUN 和 DNS 一起停。
→
模式：规则 / 全局 / 直连和 Clash 系客户端、Surge 一致。去掉「方案」，保留一个「恢复推荐分流」。
实时信息写成了句子“12 个规则集中已下载 12 个”“最早更新于 3 小时前”，延迟、用量也都是副标题文字。
→
用形状和颜色表达延迟着色、用量进度条、状态圆点、国旗、策略色。文字只在补充信息时出现。
日常入口太少换节点要开启动器或进设置，没有菜单栏入口。
→
代理菜单栏图标模式、各策略的节点、测速都在菜单里，两次点击完成。
看不到流量实际怎么走某个网站走错了，只能猜它属于哪个分类再去改。
→
活动页每个连接命中的分流和出口一目了然，在那一行直接加规则。

美观上的问题和不直观是同一个根源：界面在描述配置，而不是展示状态。表单行、副标题和菜单本身没有错，错在它们承担了全部信息。新设计把颜色留给一件事：策略色。同一个策略在流向图的线条、节点卡片的选中框、分流的目标、菜单的圆点上都是同一种颜色，看颜色就知道流量归谁；其余部分沿用 Tinycast 的透明度色阶和语义色。

同类产品怎么做 取它们的共同点

先给状态

Clash Verge Rev 首页的当前节点、代理模式、流量统计卡片；sing-box 的仪表盘卡片；Surge 的概览页。

→ 概览，菜单顶部的状态行
一个模式开关

规则、全局、直连三种出站模式。ClashX、Clash Verge Rev、sing-box、Surge 都有，而且位置固定、随手可切。

→ 工具栏和菜单栏的模式
菜单栏随手切换

ClashX、Surge 和 sing-box 的 macOS 状态栏菜单：每个策略组一个子菜单，列出节点和延迟，当前项打勾。

→ 代理菜单栏图标
节点用卡片

Clash Verge Rev 和 sing-box 的节点卡片：名称、协议、着色的延迟，选中的那张描边。

→ 节点页，按地区分组
订阅用卡片

Clash Verge Rev 的订阅卡片：已用流量进度条、到期时间、更新时间、一键更新。

→ 订阅页，概览底部的用量
看见每个连接

Surge 的最近请求、Clash Verge Rev 的连接页：每条连接命中了哪条规则、走了哪个策略。

→ 活动页，可直接加规则

不照搬的部分：多份配置文件切换（Tinycast 只有一份配置，订阅只提供节点）；直接编辑 YAML（保留只读的「查看生成的配置」）；单独的日志页（日志在 设置 › 内核 › 显示日志）。它们没有、我们有的：流向图。别家的策略组来自订阅，用户很少需要看懂整体；Tinycast 的策略和分流由用户自己搭，所以需要一张能看全的图。

落地方案 只动界面，不动数据和助手

保留

  • 数据模型原样：ProxyProfile、订阅、策略、分流、我的规则；现有配置无需迁移。
  • ProxyManager、配置生成、内核 API、内核升级与回滚。
  • TUN 助手一行不改，ProxyHelperWire.version 不变，不需要重新输入管理员密码。
  • 启动器的「选择节点」「添加代理规则」，对话框和 HUD。
  • 各编辑器的字段与校验逻辑，换到新窗口的面板里。

新增

  • 代理窗口：照 AI 对话窗口的 NSSplitViewController 做，系统侧边栏材质加统一工具栏，五个页面。
  • 流向图：SwiftUI Canvas 配合锚点偏好绘制。
  • 代理菜单栏项：和日历一样是独立的菜单栏项；子菜单用分区标题、副标题和角标。
  • 内核接口：/traffic 每秒一行 JSON，复用读日志的流式读取；/connections 只在活动页可见时轮询。
  • 模式加入「直连」并持久保存；新偏好 showsProxyInMenuBar，同时登记 SettingsFileKey。
  • 网址测试：经混合端口真实发起一次连接，从 /connections 读出命中的规则和出口后立即断开。

去掉

  • 设置 › 代理 的「节点」「策略」「分流」三页和节点池弹窗，设置里只剩偏好。
  • 「方案」选择器（智能分流、全局代理、大陆直连、自定义）和「临时全局代理」。
  • 启动器的「代理分流」「代理策略」两个屏幕；命令保留，改为打开窗口对应页面。
  • 延迟着色阈值从 300 ms 改为 150 ms，否则几乎所有节点都是绿色，颜色失去意义。
第一步 · 骨架与概览窗口、侧边栏、工具栏的模式与开关；概览的出口、流量、流向、状态；三态模式；菜单栏项。
第二步 · 管理页面节点页（策略标签、卡片、全部节点）；分流页（拖动排序、目标菜单、网址测试）；订阅页；编辑面板迁过来。
第三步 · 收尾与验收活动页；设置瘦身；启动器文案；文档、测试和端到端验收。全部验证通过后再一起提交。

需要你确认的 每项都有推荐答案

管理界面放进独立的代理窗口？推荐：是。另一个做法是继续留在设置里只换样式，但设置窗口是偏好表单，放不下流向图和节点卡片这种实时内容。
去掉「方案」，统一用规则、全局、直连三种模式？推荐：是。三个预设里「全局代理」和临时全局重复，「大陆直连」和「智能分流」只差广告拦截与 Apple 直连，留一个「恢复推荐分流」就够了。
活动页放进第一批？推荐：放。它是看懂分流、发现走错的网站最直接的办法，实现上只是在页面可见时轮询一个接口。
菜单栏代理图标默认显示？推荐：开启代理功能后默认显示，可以在设置里关掉，或拖出菜单栏。
