# 长截图拼接质量改进计划

日期：2026-10-22。依据：用户录屏对比（竞品 IMG_6478/6481，Tinycast IMG_6480）、同期 Capture 日志、
`ScrollStitchPolicy` 离线复现，以及 7 个开源长截图项目的源码阅读。

## 现状与证据

- 14:44:00–14:44:10 的一次手动长截图（AI Chat 整窗，1910 × 1314 px）记录了 7 次
  `Scroll alignment lost`，最终 24 段、1910 × 9074；录屏中多次出现“接不上了，往回滚一点就能继续”。
- 竞品同场景无中断提示，支持从下往上滚，并在选区旁实时显示长图缩略条。
- 离线复现：合成代码页偏移 60/200/500 均正确拼接；最右一列加上随滚动移动的 overlay 滚动条后，三者全部
  `uncertain`。采样列包含选区两端像素，而匹配要求每列至多一个窗口不一致。
- AI Chat 的对话区使用 `EdgeDissolve`：渐隐带固定在屏幕上，内容在其下移动，既不是固定栏也不随内容移动，
  每列都有多个窗口不一致；新段又总从帧底部切，渐隐的行会留在每条接缝上。
- 浮动按钮、固定侧栏同理：文档原先明确让它们使匹配 `uncertain`。

## 开源实现对比

| 项目 | 帧 / 等待稳定 | 配准 | 固定与浮动元素 | 反向滚动 | 实时预览 |
| --- | --- | --- | --- | --- | --- |
| Snapzy | SCStream 30fps，缩略图 100ms 不变 | Vision 多区域 + 粗精搜索，位移先验，整段重叠逐点验证 | 8 对帧投票学习上下栏与侧栏 | 代码存在，实际只向下 | 浮动预览窗 |
| ScrollSnap | SCScreenshot 每 0.25s | Vision 5 段投票，≥4 段一致 | 无 | 连续两帧反向即裁尾 | 未见 |
| macshot | 连续两次截图相同 | Vision，先裁掉吸顶栏与滚动条 | 识别一次 | 不支持 | 侧边预览 |
| Capso | SCScreenshot 每 150ms | Vision，避开上下固定区 | 识别一次 | 不支持 | 左侧预览 |
| JHTNT（Android） | 手动触发 | 亮度 + 梯度搜索，三列区域须一致 | 自动底栏 | 双向搜索 | 有 |
| ShareX | 每步截图，固定 300ms | 整行精确相等 | 底栏 | 不支持 | 结束后 |

共同做法：滚动条与静止区域先排除再配准；多个区域多数一致即接受，而非每列全票；接缝避开边缘渐隐。

## 整体评审（2026-10-22）

P0 的三轮修正都是看到一种真实页面失败、再调一个阈值，第三次实测仍在 7011 行处断开且不再恢复。
问题在结构上，不在某个阈值。

| | Tinycast 现状 | macshot | Snapzy | ScrollSnap / Capso |
| --- | --- | --- | --- | --- |
| 何时取帧 | 定时轮询，动时约 55ms 一帧 | 滚轮事件触发，0.15s 节流；停 0.25s 后取稳定帧 | SCStream 30fps 环形缓冲；按滚轮累计距离触发提交 | 定时 0.25s / 0.15s |
| 位移估计 | 自写的 32 列比对，十余个经验阈值 | Vision 平移配准，先裁掉吸顶栏与滚动条 | Vision 多区域 + 粗精搜索 + 整段逐点验证 | Vision，ScrollSnap 5 段投票 |
| 运动先验 | 无 | 无 | 滚轮累计位移作为期望值，约束搜索并否决矛盾结果 | 无 |
| 对不上时 | 停住，等用户往回滚 | 把参照换成当前帧，可能静默漏段 | 连续两次失败暂停并提示“慢一点” | 丢弃该帧 |
| 可观测性 | 只有计数日志 | 无 | 导出未对齐帧与逐次指标 | 无 |
| 回归数据 | 合成帧 | 无 | 单元测试 + 导出帧 | 无 |

结论：

1. 自写比对器的阈值都是在合成数据上调出来的，每遇到一种新页面就可能失效。业界普遍用 Vision 做位移估计，
   再用一道严格验证兜底。我们的严格验证（防重复版式）值得保留，但不该同时承担估计职责。
2. 没有利用滚轮位移。监听全局 `scrollWheel` 不需要辅助功能权限，就能知道大概滚了多远：搜索可以只看附近；
   遇到重复版式时可以排除不合理的候选；滚太快时能准确提示“慢一点”，而不是笼统说“接不上”。
3. 对不上就卡死。至少应该再拿更早的几段参照帧去比对；确实接不上时明确告诉用户缺了一段，而不是静默跳过。
4. 没有真实数据回路。三次都靠临时构建去取帧；应该内置“导出未对齐帧”的开发开关，并把真实帧序列放进回放用例。

## 重构路线

- [ ] A 可观测：开发开关导出未对齐的帧对与判定过程；真实帧序列回放用例
      （AI Chat 带侧栏、Safari、Xcode、PDF、Finder 列表），作为每次改动的回归门槛。
- [ ] B 运动先验：监听滚轮累计位移，按位移触发取帧；先在期望位移附近搜索，否决与先验矛盾的结果；
      超出可达范围时提示“慢一点”。
- [ ] C 估计与验证分离：Vision 平移配准做估计（按列和行带排除静止区域、多段投票），现有比对器只负责验证。
- [ ] D 恢复：失败时与最近几段参照比对；仍失败则暂停并说明缺口，不静默跳段。
- [ ] E 质量：多帧学习的吸顶栏与侧栏、靠近边缘时延迟提交、在低差异行处下刀。
- [x] F 窗口选择跳动（IMG_6482）：选中窗口后点长截图，12.8s 处选区先从整窗跳到窗口内的滚动区域，
      并闪过一帧过渡画面（侧边操作栏消失、底栏换成另一套，冻结画面与选区错位）。
      - 选区跳到滚动区域：已随 P0 修正，现在保留整窗。
      - 过渡闪烁：`scrollWindow` 原先先切模式、再重设选区，然后异步准备采样，等待期间遮罩已换成长截图界面。
        现在直接用窗口范围启动，与已选区域的路径一致，控件就绪后一次切换。用户已确认。

## P0：断档（本轮）

- [x] 采样列避开选区两端，overlay 滚动条不再进入匹配（`ScrollFrameReader.sample`）。
- [x] 在最佳位移下不一致、但在零位移下一致的窗口视为静止内容（侧栏、浮动按钮），不计入一致性和误差；
      静止窗口超过有内容窗口的三分之一仍判 `uncertain`，以免把局部滚动的大片静止区域拼成长图。
- [x] 重叠区两端多数列同时不一致的行带视为不稳定边缘（渐隐、遮罩），排除出一致性判断；底部的带并入
      `fixedTrailing`，追加时用新帧替换上一段的渐隐行，接缝不再残留渐隐。上限为帧长的六分之一。
- [x] 重复版式的保护不变：移动过的列在错误位移下仍不一致，且零位移也不一致，照旧 `uncertain`。
- [x] 回归用例：滚动条、渐隐带、浮动按钮、固定侧栏、重复版式、局部滚动。
- [x] 真实帧回放（AI Chat 整窗、侧栏展开）暴露的三处，均已修正：
  - 静止窗口上限从三分之一放宽到三分之二。侧栏字多、代码区留白多时，静止窗口占 35%–42%。
  - 侧栏字少，错位时误差只有 6–12。改为“静止解释优于移动解释”即视为静止，不再要求误差超过 12。
  - 候选搜索剔除零位移即相同的列，否则侧栏、标题栏、输入框把最佳候选拉到 ±2。
- [x] 选中窗口再点长截图时保留整个窗口作为区域，不再收窄到窗口内最大的滚动区域；
      删除 `largestScrollView`、`CaptureElementAccess.scrollArea` 与 `captureScrollerClearance`。

已知限制：整窗区域里侧栏在每段都会出现，侧栏文字可能在接缝处被切断；回弹（rubber band）时
保留的最远帧可能在结尾带入一段越界空白，留待 P1。

滚动条只靠列内缩避开：滑块以自己的速度移动，静止判据解释不了它；为它放宽单列一致性会重新打开
重复版式误拼的口子，故不放宽。区域内部的嵌套滚动条仍会使匹配 `uncertain`。

未采用多帧投票学习固定区域：逐窗口的零位移判据已覆盖本次的侧栏与浮动按钮，且无需跨帧状态；
真实页面若仍出现固定区域误判，再引入投票。
